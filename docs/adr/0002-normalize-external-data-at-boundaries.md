# 0002. 외부에서 들어오는 값은 경계에서 정제·정규화한다 (배포 환경변수 + RTDB 스냅샷)

- 상태: 제안 (사후 기록 — 구현·배포 완료 후 작성, 사용자 승인 대기)
- 날짜: 2026-08-25
- 결정자: architect
- 관련 결정: DECISIONS.md #4, #5

## 맥락

배포 후 "로컬에서는 되던 기능이 배포하니 안 된다"는 장애가 두 갈래로 발생했다. 둘 다 원인이 같다 — **외부 표현을 그대로 도메인/설정에 밀어 넣었다.**

1. **배포 플랫폼 환경변수**: Vite는 로컬 환경변수 파일을 dotenv로 파싱하며 값을 감싼 따옴표를 제거하지만, Vercel 대시보드에 입력된 값은 원문 그대로 번들에 인라인된다. 실제로 `VITE_FIREBASE_*` 7개가 전부 큰따옴표를 포함해 저장되어 있었고 (인용 — 대시보드 화면은 이 세션에서 직접 확인하지 않음), `databaseURL`이 `"https://...app"` 형태가 되어 REST 404 / WebSocket `ERR_NAME_NOT_RESOLVED`를 일으켰다.
2. **RTDB 스냅샷**: Realtime Database는 빈 배열·빈 객체를 저장하지 않는다. 로그가 하나도 없는 인원은 `logs` 키가 통째로 사라진 채 읽히고, `member.logs.length` / `[...member.logs]`가 런타임에 터졌다. 로컬 BroadcastChannel 모드는 localStorage가 빈 배열을 그대로 보존하므로 재현되지 않던 **배포 전용 결함**이다.

## 검토한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| A. 배포 대시보드 값을 사람이 올바르게 다시 입력 (코드 변경 없음) | 즉시 조치 가능, 코드 증가 없음 | 같은 실수가 재발하면 같은 장애가 재발한다. 실패가 조용해서 발견이 늦다 |
| B. 사용처마다 옵셔널 체이닝·기본값 (`member.logs?.length ?? 0`) | 국소적 수정, 파일 하나씩 고칠 수 있음 | 누락 지점이 계속 생긴다 — 실제로 5곳에 흩어져 있었다 (인용 — 코드 스캔 결과, 이 세션에서 5곳 재계수하지 않음) |
| C. 경계 모듈에서 일괄 정제·정규화 (채택) | 결함 유형별 방어선이 한 곳, 테스트 대상이 순수 함수 1개로 수렴 | 읽기 경로가 늘 때마다 정규화 호출을 잊으면 다시 뚫린다 |

## 결정

C를 채택한다. 외부 표현과 내부 모델의 차이를 **경계 한 곳에서 흡수**한다.

- `src/services/firebase-config.ts`의 `sanitizeConfigValue()`가 앞뒤를 모두 감싼 따옴표(짝이 맞을 때만)·공백·끝 슬래시를 제거한 뒤 Firebase 설정에 주입한다. 대시보드 값을 사람이 올바르게 넣는 것에만 의존하지 않는다.
- `src/domain/room-normalizer.ts`의 `normalizeRoom()` / `normalizeMember()`가 `members`, `adminMemberIds`, 인원별 `logs`, `activeStatus`를 채운 뒤 도메인 계층에 넘긴다. 읽기 경로 4곳(초기 조회·구독 콜백 등)에서 호출한다 (인용 — 호출 지점 수는 구현 보고 값, 이 세션에서 재계수하지 않음).

결정적 이유: 둘 다 "저장소/플랫폼의 표현"과 "도메인이 가정하는 표현"의 차이이며, 이 차이는 Clean Architecture상 **어댑터 경계의 책임**이다 (`.agents/skills/clean-architecture/SKILL.md` DTO 경계 항목).

## 결과 (트레이드오프 포함)

- 얻는 것: 배포 환경변수에 따옴표가 다시 섞여도 동작한다. RTDB가 키를 생략해도 도메인 코드는 항상 배열·객체를 받는다. 두 방어선 모두 순수 함수라 단위 테스트가 쉽다.
- 감수하는 것: 정규화를 거치지 않는 새 읽기 경로가 추가되면 같은 결함이 되살아난다. `normalizeRoom()`은 `...raw` 스프레드로 미지 필드를 통과시키므로, 스키마 변경 시 정규화 대상 필드를 사람이 챙겨야 한다.
- 잔여 위험: 정규화 호출 강제 수단(린트 규칙 등)은 두지 않았다 — 읽기 경로가 4곳뿐이라 비용 대비 이득이 없다고 판단했다. 경로가 늘면 재검토한다.
